The Critical Edge Case — Mid-Cycle Correction
⚡ What if a systematic error is found AFTER the matrix is locked?
Example: It's March 2025. Matrix v2025 is locked. A BOR hearing reveals that all 847 Historic Richland parcels were systematically over-assessed because the R6 factor was miscalibrated. The assessor needs to act.
Option A: Correction Within Cycle
Create v2025.1 (patch). Document the correction with a Calibration Memo. Apply correction only to affected parcels. Both v2025.0 and v2025.1 remain in the audit trail.
✓ Transparent · Defensible · WAC 458-07 compliant
Option B: Feeds 2026 Calibration Only
The locked matrix stays locked. The finding feeds directly into the 2026 draft as a high-priority calibration item. AI marks R6 factor as "evidence-flagged" for next cycle.
Lower risk · No mid-cycle disruption · Some taxpayers wait a year
TerraFusion should support BOTH. Which path the assessor takes is a policy decision — AI flags the choice, documents whatever is chosen.

My Recommendation — How TerraFusion Should Model This

Git-model versioning for cost matrices. Every matrix has a semantic version (v2025.0, v2025.1, v2026.0-draft). The Calibration Workbench is always working on the current draft. Draft → Review → Approved → Locked is a one-way state machine per version. Locked matrices are immutable — always queryable for BOR defense. AI compares across versions, detects drift, projects forward.

Two simultaneous views always present: current locked matrix (what's applied to parcels right now) and next year draft (what's being built). The appraiser sees both side-by-side with the diff highlighted.

Mid-cycle corrections create patch versions (v2025.1) that are themselves a full Draft → Review → Approve → Lock cycle — just scoped narrower and faster.
