# June 10 Demo Click Path

## Rule

No wandering. The demo follows this path only.

## Primary Demo Path

1. Open TerraFusion OS.
2. Select or show Benton County as `Runtime Pilot`.
3. Confirm the top bar shows county, role, department/context, and runtime status.
4. Open Property Workbench.
5. Search or select a Benton parcel.
6. Show property summary from TerraFusion DB/API-backed data.
7. Show CAMA/improvement/property characteristics only where sourced and defensible.
8. Show sales/comparable data only where real and sourced.
9. Show evidence/provenance note: Benton data is PACS-derived and loaded into TerraFusion DB.
10. Show Hostinger/runtime identity or health proof if available in the rehearsal environment.
11. Show snapshot/evidence/manifest posture.
12. Switch to another Washington county.
13. Show that county as onboarding/provenance/intake, not runtime enabled.
14. Show runtime operations are blocked or labeled for non-Benton counties.
15. Return to the final claim sheet.

## Required Talking Points

- TerraFusion launches the Washington county operating model.
- Benton is runtime-proven first.
- Other counties are represented as sovereign onboarding/provenance/intake workspaces.
- Runtime truth is TerraFusion DB -> TerraFusion API -> TerraFusion apps.
- PACS explains Benton data origin; PACS is not the deployed runtime path.
- County Data Intake is governed onboarding only and has `canonicalImportAllowed: false`.

## Do Not Say

- All counties are live.
- All counties are certified.
- Hostinger is connected to PACS.
- TerraFusion Sync is fully productized.
- AI valuations are official.
- Unfinished modules are production-ready.
