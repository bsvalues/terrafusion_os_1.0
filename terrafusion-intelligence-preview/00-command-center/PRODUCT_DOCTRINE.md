# TerraFusion Product Doctrine

> People remember decisions, not software.

---

## Mission

Transform expertise into capability.

---

## Product Identity

| Product | Transformation |
|---------|---------------|
| **Atlas** | Data → Decisions |
| **Academy** | Knowledge → Capability |
| **OS** | Capability → Action |

---

## Principles

### 1. Progressive Depth

Five layers. Everyone stops where they succeed.

1. **What is it?** — Anyone understands
2. **Why does it matter?** — Non-experts stop here and succeed
3. **What should I do?** — Action items
4. **Show me the evidence.** — Comparable sales, ratio analysis, levy breakdowns
5. **Show me the technical details.** — COD statistics, IAAO standards

Gabe stops at Layer 2. Danny jumps to Layer 5. Both succeed.

### 2. Intelligence Density

More meaning per screen. Not more information.

Every element must support a decision or provide evidence for one. If it does neither, cut it.

More value = less noise.

---

## Rules

1. **People remember decisions, not software.** Design for what they'll remember tomorrow, not what impresses them today.

2. **Every feature must make a decision easier or provide evidence for one.** If it doesn't, it doesn't ship.

3. **Capability is more valuable than dependency.** The goal is not "they need TerraFusion." The goal is "TerraFusion made them more capable." That's what creates adoption.

4. **Users shape the product.** Evidence beats intuition. When the Memory Report and founder vision conflict, the Memory Report wins.

5. **The software is the delivery mechanism.** The product is the transformation. Atlas is not a property report — it's the decision the assessor makes after reading it. Academy is not a knowledge base — it's the confidence Gabe feels when he walks into a meeting.

## The Tests

Before any feature, any change, any addition:

**What decision becomes easier?**

If you can't answer that, the Memory Report has already told you what to do.

Before any presentation, any explanation, any pitch:

**Will this survive transmission?**

The conference is not about what you say. It's about what people say after they leave. If the language survives without you in the room, the product is real.

---

## How This Doctrine Was Built

Most product doctrine is invented, then tested. This one was discovered.

```
User Experience → Memory → Language → Doctrine
```

Not:

```
Doctrine → Language → Product → Hope
```

Five personas used the product independently. We recorded what they remembered. We studied what language they used. The doctrine is what emerged.

That's why it feels real. It wasn't imposed. It was extracted from evidence.
