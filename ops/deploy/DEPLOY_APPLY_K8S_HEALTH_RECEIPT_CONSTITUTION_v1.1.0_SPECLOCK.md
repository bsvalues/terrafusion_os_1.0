# Deploy Apply K8s + Health + Receipt Constitution v1.1.0 — SpecLock

> **Status**: LOCKED — Amendment requires RFC + Breaker approval + shadow review  
> **Created**: 2024-12-20  
> **Base Versions**: v1.0.0, v1.0.1 (hardening)  
> **Scope**: K8s-only apply with health checks and enriched receipts

## Overview

This SpecLock upgrades Deploy Apply from governance-only (v1.0.0/v1.0.1) to perform actual Kubernetes apply and health checks, producing enriched receipts while preserving all verify-first and safety invariants.

**Key Constraint**: v1.1.0 supports **K8s mode ONLY**. Compose/Docker orchestration is explicitly OUT OF SCOPE.

---

## Commands

### 1. `tf deploy apply`

```bash
tf deploy apply --env <dev|techsupport|prod> --bundle <dir> [--namespace <ns>] [--timeout <sec>] [--dry-run] [--ci]
```

**Purpose**: Execute Kubernetes deployment from a verified RuntimeCert bundle.

**Required Flags**:
- `--env <env>`: Target environment (dev, techsupport, prod)
- `--bundle <dir>`: Path to RuntimeCert bundle directory

**Optional Flags**:
- `--namespace <ns>`: Target Kubernetes namespace (REQUIRED if not inferable; see Namespace Rules)
- `--timeout <sec>`: Health check timeout per deployment (default: 120, max: 600)
- `--dry-run`: Validate and produce receipt without executing mutations
- `--ci`: JSON-only output to stdout

### 2. `tf deploy receipt`

```bash
tf deploy receipt --bundle <dir> [--ci]
```

Unchanged from v1.0.0. Returns existing deployment receipt.

## Bundle K8s Manifest Directory

**Location**: `<bundle>/k8s/`

**Requirements**:
- Directory MUST exist if apply is non-dry-run
- MUST contain at least one `.yaml` or `.yml` file
- Symlinks within `k8s/` directory are NOT allowed (reuse v1.0.1 policy)
- Path escape (via `..` or absolute paths) is blocked

**Bundle Structure (v1.1.0 addition)**:
```
<bundle>/
├── manifest.json
├── checksums.sha256
├── bundle_meta.json
├── proofs/
│   ├── gate.json
│   ├── agent.json
│   ├── deploy.json
│   ├── marketplace.json
│   └── deploy_receipt.json   # Generated by apply
└── k8s/                       # NEW in v1.1.0
    ├── deployment.yaml        # Kubernetes manifests
    ├── service.yaml
    └── deployments.txt        # OPTIONAL: List of deployments to health-check
```

### deployments.txt (Optional Health Check Manifest)

If present at `<bundle>/k8s/deployments.txt`, this file lists deployments to health-check:
```
deployment/api-gateway
deployment/consciousness-engine
deployment/terrafusion-api
```

If NOT present, apply will query `kubectl get deploy -n <ns> -o name` after apply to determine deployments.

## Namespace Rules

**Fail-Closed Policy**: v1.1.0 does NOT provide environment-to-namespace defaults.

| Scenario | Behavior |
|----------|----------|
| `--namespace` provided | Use provided namespace |
| `--namespace` NOT provided | Exit 2 with `NAMESPACE_REQUIRED` |

**Namespace Existence**: Apply requires namespace to exist. No auto-creation.

```bash
# MUST succeed before apply
kubectl get namespace <ns>
```

If namespace does not exist: exit 1 with `NAMESPACE_NOT_FOUND`.

## Timeout Rules

| Setting | Value | Description |
|---------|-------|-------------|
| Default | 120 seconds | Per-deployment rollout timeout |
| Maximum | 600 seconds | Hard cap (10 minutes) |
| Minimum | 10 seconds | Sanity floor |

If `--timeout` exceeds maximum or falls below minimum, clamp to bounds (no error).

## Constitutional Invariants

### A. Verify-First + TOCTOU (Carry from v1.0.1)

- Bundle MUST pass `tf release verify` before any kubectl operations
- Hash captured after verify, re-compared before receipt write
- Drift → exit 1 `BUNDLE_CHANGED`, NO receipt

### B. K8s Toolchain Validation (Preflight)

Before any kubectl operations:
1. `command -v kubectl` must succeed (exit 1 `KUBECTL_MISSING` if not)
2. `kubectl config current-context` must succeed (exit 1 `KUBE_CONTEXT_UNAVAILABLE` if not)

### C. Apply Source Allowlist

- Apply ONLY from `<bundle>/k8s/` directory
- Symlink check on `k8s/` directory itself
- No arbitrary `--file` paths outside bundle

### D. Namespace Safety

- Explicit `--namespace` required (fail-closed)
- Namespace must exist (no auto-create)
- Namespace name sanitized (alphanumeric + dash only, max 63 chars)

### E. Health Checks (Timeboxed)

For each deployment in `deployments.txt` or discovered via kubectl:
```bash
kubectl rollout status -n <ns> deploy/<name> --timeout=<timeout>s
```

- Timeout per deployment (not cumulative)
- All deployments must pass for overall success
- First failure/timeout → exit 1, receipt written with failed status

### F. Receipt Enrichment

See Receipt Schema v1.1.0 below.

Backward-compatible additive changes to v1.0.0 schema:

```json

  "version": "1.1.0",
  "timestamp": "<RFC3339Z>",
  "environment": "dev|techsupport|prod",
  "mode": "k8s",
  "bundle": {
    "path": "<sanitized absolute path>",
    "hash": "<sha256 of checksums.sha256 file>",

  },
  "git": {
    "sha": "<HEAD sha or null>",
    "tag": "<exact tag or null>"
  },
  "action": "apply|dry_run",
  "status": "success|failed|dry_run",
  "steps": [
    {"name": "verify", "status": "pass|fail", "message": "..."},
    {"name": "preflight", "status": "pass|fail", "message": "..."},
    {"name": "execute", "status": "pass|fail|skip", "message": "...", "details": {...}},
    {"name": "health", "status": "pass|fail|skip|timeout", "message": "...", "details": {...}}
  ],
  "error": {"code": "...", "message": "..."} | null,
  "k8s": {
    "context": "<kubectl current-context>",
    "namespace": "<target namespace>",
    "applied": [
      {"kind": "Deployment", "name": "api-gateway", "namespace": "<ns>"},

## CI Purity

When `--ci` flag is present:

1. **JSON-only stdout**: No ANSI codes, no kubectl progress output
2. **kubectl output capture**: All kubectl stdout/stderr captured, not streamed
3. **Valid JSON**: Must parse with `python3 -m json.tool`
4. **Summary in JSON**: kubectl output summarized in receipt fields

## Execution Flow

```
1. Parse arguments
2. Validate invocation (env, bundle, namespace)
3. Check MODE == k8s (exit 2 if not)
4. Symlink checks (bundle root, manifest.json, proofs/, checksums.sha256, k8s/)
5. Verify bundle (tf release verify)
6. Capture verified_hash
7. Toolchain validation:
   a. command -v kubectl
   b. kubectl config current-context
8. Namespace validation:
   a. Sanitize namespace name
   b. kubectl get namespace <ns>
9. Manifest validation:
   a. <bundle>/k8s/ exists
   b. Contains .yaml/.yml files
10. If dry-run: skip to step 14
11. Execute: kubectl apply -n <ns> -f <bundle>/k8s/
12. Parse applied resources
13. Health checks:
    a. Determine deployments (deployments.txt or kubectl query)
    b. For each: kubectl rollout status --timeout=<timeout>s
    c. Record results
14. TOCTOU check (pre_write_hash == verified_hash)
15. Build and write receipt
16. Output (JSON if --ci, formatted otherwise)
```

## Security Considerations

1. **Bundle-contained only**: No external manifest paths
2. **Symlink protection**: v1.0.1 checks extended to k8s/ directory
3. **Namespace sanitization**: Reject control characters, newlines, ANSI
4. **TOCTOU hardening**: Re-hash before receipt write
5. **Timeout enforcement**: Prevent indefinite hangs
6. **kubectl output isolation**: Captured, not streamed to stdout in --ci
