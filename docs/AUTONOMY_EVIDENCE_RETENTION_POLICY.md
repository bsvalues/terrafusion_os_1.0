# TerraFusion Autonomy Evidence Retention Policy

**Version:** autonomy-evidence-retention.v1  
**Effective Date:** 2026-01-31  
**Classification:** Public / County Operations

---

## Purpose

This policy establishes the retention schedule for Autonomy Evidence Bundles generated by the TerraFusion AI governance system. Evidence bundles are cryptographically-signed audit packets that document every automated change made by the Autonomy subsystem.

---

## Scope

This policy applies to:

- Autonomy Evidence Bundles (ZIP files with SHA256 manifests)
- Evidence Index files (JSON records of all runs)
- Apply Proofs (cryptographic proof trails)
- Performance Plans (machine-generated optimization plans)
- CIO Dashboards (offline HTML viewers)

---

## Retention Schedule

### Standard Retention (Default)

| Artifact Type | Retention Period | Storage Location |
|---------------|------------------|------------------|
| CI Workflow Artifacts | **90 days** | GitHub Actions Artifacts |
| Evidence Bundle ZIP | **90 days** | GitHub Actions Artifacts |
| Evidence Index JSON | **90 days** | GitHub Actions Artifacts |
| PR-attached artifacts | **Until PR is closed + 90 days** | GitHub PR Artifacts |

### Extended Retention (Merged PRs) — Release Evidence Channel

When a PR with autonomy changes is **merged to main**, the evidence bundle is automatically published to a GitHub Release for extended retention.

| Condition | Retention Period | Storage Location | Automation |
|-----------|------------------|------------------|------------|
| PR merged to main | **1 year** | GitHub Release (`autonomy-evidence/YYYY-MM`) | `autonomy-evidence-publisher.yml` |
| Tagged release | **2 years** | Release Assets | Manual escalation |
| Incident label applied | **7 years** | GitHub Release (`autonomy-incident/YYYY`) | `autonomy-incident-publisher.yml` |

#### Release Evidence Channel Details

- **Tag Format:** `autonomy-evidence/YYYY-MM` (monthly rollup)
- **Assets Published:**
  - `autonomy-evidence-<runId>.zip` — Complete evidence bundle
  - `autonomy-evidence-<runId>.manifest.json` — SHA256 integrity hashes
  - `autonomy-evidence-index.json` — Evidence ledger entry
  - `autonomy-dashboard-<runId>.html` — Offline CIO viewer
  - `autonomy-dashboard-<runId>.json` — Machine-readable dashboard

#### Security Posture

- Workflow only runs on merged PRs to main
- Bundle must pass `perf:verify-bundle --strict` before publish
- Minimal permissions: `contents: write`, `pull-requests: read`
- No artifacts downloaded from untrusted sources

#### Verification

Download any bundle from the Release and verify offline:

```bash
pnpm perf:verify-bundle --zip autonomy-evidence-<runId>.zip --strict
```

### Incident Retention Channel (7 Years)

When a PR is labeled with `incident`, it is automatically promoted to the 7-year incident retention channel.

#### Trigger Conditions

| Event | Action |
|-------|--------|
| PR closed (merged) + incident label | Immediate promotion |
| PR labeled (after merge) | Retroactive promotion |

#### Incident Release Channel Details

- **Tag Format:** `autonomy-incident/YYYY` (yearly rollup for 7-year retention)
- **Assets Published:**
  - `autonomy-incident-pr<PR#>-<runId>.zip` — Complete incident evidence bundle
  - `autonomy-incident-pr<PR#>-<runId>.manifest.json` — SHA256 integrity hashes
  - `autonomy-incident-pr<PR#>-index.json` — Incident evidence ledger
  - `autonomy-incident-pr<PR#>-dashboard.html` — Offline CIO viewer

#### Evidence Index Incident Fields

When an incident is recorded, the evidence index includes:

```json
{
  "incident": true,
  "incidentSource": {
    "pr": 123,
    "mergedAt": "2026-01-31T12:00:00Z"
  },
  "releaseTag": "autonomy-incident/2026"
}
```

#### Incident Safety Invariants

- Incident label **cannot** be applied by bots (GitHub policy)
- Once a bundle is promoted to incident tier, retention is **sticky**
- Never modifies the original monthly evidence release
- Never overwrites existing incident entry for same PR
- Rollback commands are included in release notes

#### Dashboard Incident Display

When viewing an incident-tier bundle, the dashboard shows:
- **Red "Incident (7 years)" badge** in retention tier
- Incident PR number and merge details
- Enhanced rollback instructions

### Audit Retention (Jurisdiction-Dependent)

| Jurisdiction Requirement | Retention Period | Notes |
|--------------------------|------------------|-------|
| FISMA (Federal) | **3 years** | As per NIST SP 800-53 |
| State Records Retention | **5-7 years** | Varies by state |
| Legal Hold | **Indefinite** | Until hold is released |

## Integrity Requirements

### Verification

Every retained bundle must pass integrity verification:

```bash
pnpm perf:verify-bundle --zip <bundle.zip> --strict
```

### Manifest Requirements

- Schema: `terrafusion.autonomy.evidence.v1`
- Hash Algorithm: SHA-256
- All files listed in manifest must exist
- All SHA-256 hashes must match

### Non-Auditable Bundles

A bundle is **NOT auditable** unless:

1. `perf:verify-bundle --strict` passes with exit code 0
2. MANIFEST.json is present and valid
3. All referenced files are intact

---

## Custody Chain

### Generation

1. CI workflow generates evidence bundle
2. Bundle is verified immediately after generation
3. Verification result is recorded in Evidence Index
4. All artifacts uploaded to GitHub Actions

### Access Control

| Role | Access Level |
|------|--------------|
| County CIO | Full read access to all bundles |
| IT Staff | Read access to own department bundles |
| Auditors | Read access with audit request |
| Public | No access (internal records) |

### Export Procedures

When bundles are exported for audit:

1. Download from GitHub Actions artifacts
2. Verify integrity using `perf:verify-bundle`
3. Document chain of custody
4. Store copy in county records system

---

## Exceptions

### Early Deletion

Bundles may be deleted early only if:

- Legal counsel approves in writing
- No pending audits or investigations
- County CIO authorizes

### Extended Retention

Bundles must be retained beyond standard period if:

- Subject to legal hold
- Part of active investigation
- Required by regulatory body
- Labeled as "incident"

---

## Implementation

### Automated Enforcement

- GitHub Actions artifact retention: 90 days (default)
- Workflow uploads all artifacts with `retention-days: 90`
- Evidence Index tracks retention policy version

### Manual Procedures

1. **Monthly Review**: IT staff reviews for incident labels
2. **Quarterly Audit**: CIO reviews evidence index for completeness
3. **Annual Archive**: Merged PR bundles copied to long-term storage
