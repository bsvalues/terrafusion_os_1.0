# R3.0 PostGIS Migration Runbook

## Overview

Upgrade ParcelGeometry from GeoJSON TEXT + Haversine to PostGIS native geometry with dual-mode support (PostgreSQL production, SQLite development).

---

## 1. Migration Prechecks

Before executing:

```bash
# Verify PostgreSQL with PostGIS extension
psql -c "SELECT PostGIS_Version();"
# Expected: "3.x.x" or higher

# Verify current schema state
psql -c "\d parcel_geometries;"
# Expected: geo_json TEXT, centroid_lat DOUBLE, centroid_lng DOUBLE

# Count rows for backfill estimation
psql -c "SELECT COUNT(*) FROM parcel_geometries;"
psql -c "SELECT COUNT(*) FROM parcel_geometries WHERE geo_json IS NOT NULL;"
```

## 2. Provider Detection Rule (Source of Truth)

Runtime provider detection uses `DbContext.Database.ProviderName`:

```csharp
bool IsPostgres => Database.ProviderName == "Npgsql.EntityFrameworkCore.PostgreSQL";
bool IsSqlite   => Database.ProviderName == "Microsoft.EntityFrameworkCore.Sqlite";
```

This is the **single source of truth** for all spatial behavior branching. No environment variables, no config flags — provider name only.

## 6. GeoJSON Validity / Backfill Strategy

### On INSERT/UPDATE (going forward)
When a geometry is upserted:
1. Parse GeoJSON string → NTS Geometry object (using `GeoJsonReader`)
2. Set SRID = 4326 (WGS84)
3. Store in both `geo_json` (TEXT) and `geometry` (native) columns
4. Compute centroid from NTS geometry
5. Store centroid in both `centroid_lat/lng` (doubles) and `centroid_point` (PostGIS point)

### Backfill of existing data
For rows with `geo_json IS NOT NULL AND geometry IS NULL`:

```sql
-- PostGIS backfill (run as one-time migration step)
UPDATE parcel_geometries
SET geometry = ST_SetSRID(ST_GeomFromGeoJSON(geo_json), 4326),
    centroid_point = ST_Centroid(ST_SetSRID(ST_GeomFromGeoJSON(geo_json), 4326))
WHERE geo_json IS NOT NULL
  AND geometry IS NULL;
```

### Invalid GeoJSON handling
```sql
-- Check for invalid GeoJSON before backfill
SELECT parcel_id, LEFT(geo_json, 100)
FROM parcel_geometries
WHERE geo_json IS NOT NULL
  AND ST_IsValid(ST_GeomFromGeoJSON(geo_json)) = false;
```

If invalid rows found:
- Log them as warnings
- Skip backfill for those rows (keep TEXT, set geometry = NULL)
- Mark with `source = 'invalid_geojson'` for manual review

## 7. SQLite No-Op Behavior

When running on SQLite:
- **ParcelGeometry.Geometry** property exists but is ignored in EF mapping:
  ```csharp
  if (IsSqlite)
      entity.Ignore(e => e.Geometry);
      entity.Ignore(e => e.CentroidPoint);
  ```
- All spatial queries use existing Haversine logic (no change from R2.10)
- No migration columns added to SQLite
- GeoJSON TEXT + centroid doubles remain the active storage path

## 8. Migration Script Shape

```csharp
// AddPostGisSpatialColumns migration
protected override void Up(MigrationBuilder migrationBuilder)
{
    // Only apply PostGIS columns when running against PostgreSQL
    if (ActiveProvider == "Npgsql.EntityFrameworkCore.PostgreSQL")
    {
        migrationBuilder.Sql("CREATE EXTENSION IF NOT EXISTS postgis;");

        migrationBuilder.AddColumn<Geometry>(
            name: "geometry",
            table: "parcel_geometries",
            type: "geometry(Geometry, 4326)",
            nullable: true);

        migrationBuilder.AddColumn<Point>(
            name: "centroid_point",
            table: "parcel_geometries",
            type: "geometry(Point, 4326)",
            nullable: true);

        // GiST spatial indexes
        migrationBuilder.CreateIndex(
            name: "ix_parcel_geometries_geometry_gist",
            table: "parcel_geometries",
            column: "geometry")
            .Annotation("Npgsql:IndexMethod", "gist");

        migrationBuilder.CreateIndex(
            name: "ix_parcel_geometries_centroid_point_gist",
            table: "parcel_geometries",
            column: "centroid_point")
            .Annotation("Npgsql:IndexMethod", "gist");

        // Backfill existing data
        migrationBuilder.Sql(@"
            UPDATE parcel_geometries
            SET geometry = ST_SetSRID(ST_GeomFromGeoJSON(geo_json), 4326),
                centroid_point = ST_Centroid(ST_SetSRID(ST_GeomFromGeoJSON(geo_json), 4326))
            WHERE geo_json IS NOT NULL AND geometry IS NULL;
        ");
    }
}

protected override void Down(MigrationBuilder migrationBuilder)
{
    if (ActiveProvider == "Npgsql.EntityFrameworkCore.PostgreSQL")
    {
        migrationBuilder.DropIndex("ix_parcel_geometries_geometry_gist");
        migrationBuilder.DropIndex("ix_parcel_geometries_centroid_point_gist");
        migrationBuilder.DropColumn(name: "geometry", table: "parcel_geometries");
        migrationBuilder.DropColumn(name: "centroid_point", table: "parcel_geometries");
    }
}
```

## 9. Rollback Procedure

### Immediate rollback (no data loss)
```bash
# Revert migration
dotnet ef database update PreviousMigrationName \
  --project TerraFusion.Data \
  --startup-project TerraFusion.API

# This drops geometry + centroid_point columns and GiST indexes
# All data remains in geo_json TEXT + centroid_lat/lng doubles
```

### Verification after rollback
```sql
-- Confirm columns removed
\d parcel_geometries;
-- Should NOT show 'geometry' or 'centroid_point' columns

-- Confirm data intact
SELECT COUNT(*) FROM parcel_geometries WHERE geo_json IS NOT NULL;
-- Should match pre-migration count
```

```sql

WHERE table_name = 'parcel_geometries'
  AND column_name IN ('geometry', 'centroid_point');

  COUNT(*) AS total,
  COUNT(geometry) AS with_native_geom,
  COUNT(centroid_point) AS with_native_centroid,
  COUNT(geo_json) AS with_geojson
FROM parcel_geometries;

-- Verify GiST indexes
SELECT indexname, indexdef
FROM pg_indexes
WHERE tablename = 'parcel_geometries'
  AND indexname LIKE '%gist%';

-- Verify spatial query works
SELECT parcel_id, ST_AsText(centroid_point)
FROM parcel_geometries
WHERE centroid_point IS NOT NULL
LIMIT 5;

-- Verify ST_DWithin proximity query
SELECT p.parcel_id, ST_Distance(p.centroid_point, q.centroid_point) AS distance
FROM parcel_geometries p, parcel_geometries q
WHERE p.parcel_id != q.parcel_id
  AND ST_DWithin(p.centroid_point, q.centroid_point, 0.01)
LIMIT 10;
```

## 11. Production Cutover Order

1. **Pre-flight**: Run prechecks (section 1)
2. **Backup**: `pg_dump -t parcel_geometries > backup.sql`
3. **Enable PostGIS**: `CREATE EXTENSION IF NOT EXISTS postgis;`
4. **Apply migration**: `dotnet ef database update`
5. **Verify backfill**: Run verification queries (section 10)
6. **Deploy code**: New code with dual-mode queries
7. **Smoke test**: Call `GET /api/atlas/parcels/{id}/nearby` and verify PostGIS path
8. **Monitor**: Check Serilog for spatial query timing (should be faster than Haversine)
9. **Cleanup**: (optional, future) Drop centroid_lat/lng columns after confidence period

## 12. AtlasController Query Changes

### Nearby parcels: Haversine → ST_DWithin

**Before (R2.10):**
```csharp
// Bounding box pre-filter + in-memory Haversine
var candidates = await _db.ParcelGeometries
    .Where(g => g.CentroidLat >= lat - delta && ...)
    .ToListAsync();
var nearby = candidates.Where(g => Haversine(...) <= radius);
```

**After (R3.0):**
```csharp
if (_db.IsPostgres)
{
    // Native PostGIS: single query, GiST-indexed
    var point = new Point(subLng, subLat) { SRID = 4326 };
    var nearby = await _db.ParcelGeometries
        .Where(g => g.CountyId == countyId
            && g.ParcelId != parcelId
            && g.CentroidPoint != null
            && g.CentroidPoint.IsWithinDistance(point, radiusMiles / 69.0))
        .OrderBy(g => g.CentroidPoint!.Distance(point))
        .Take(limit)
        .ToListAsync();
}
else
{
    // SQLite fallback: existing Haversine (unchanged from R2.10)
}
```

## Risk Assessment

| Risk | Mitigation |
|------|-----------|
| Invalid GeoJSON breaks backfill | Pre-check query identifies invalid rows; skip + log |
| PostGIS extension not installed | Prechecks verify; migration creates extension |
| Performance regression on spatial queries | PostGIS GiST should be faster; monitor query timing |
| SQLite dev environment broken | Dual-mode with `Ignore()` ensures SQLite unaffected |
| Data loss during migration | Additive columns only; rollback drops new columns |
